# Short classroom lessons

The nine classroom categories share one structure: ordered basics, a five-question basics quiz, separate advanced sections, and the existing full category quiz. Each built-in teaching step shows its idea and worked example, followed by **three understanding checks**. “Check 1 of 3” tracks the questions; students must answer each correctly before finishing the step. Wrong answers explain the idea and offer another try. Students can return to the category list and resume their card and unfinished checks on the same device.

Rhythm begins with **Note parts → Note symbols (quarter, half, whole, eighth) → Rhythm tree → Counting**. Sixteenth notes and dotted notes are taught in the advanced sections. The treble and bass paths explain the staff and the clef, then introduce both bottom-to-top mnemonic maps before asking for staff note names. Those lesson pictures number **lines 1–5** and **spaces 1–4** from bottom to top; questions use names such as **Line 3** and **Space 2**.

`classroom-learning-paths-data.js` defines the categories, sections, and runtime understanding-check resolver. All 144 built-in steps have three distinct checks (432 checks in total). Follow-ups reuse questions explicitly linked to that card’s teaching; `classroom-understanding-basics.js` and `classroom-understanding-staff.js` add targeted questions for foundational or narrower ideas. Each follow-up carries its own picture when needed. Basic rhythm does not introduce advanced note values in these checks. All existing exam coverage cards remain available: the canonical eight-category exam and its 800 questions are unchanged. The accidentals/key-signatures category remains supplemental. Optional guided practice retains the piano, rhythm-tree, and listening activities.

Each built-in basics quiz keeps five learning goals, with three already-taught question variants per goal. The quiz selects a variant and shuffles question and answer order for a fresh attempt. A resumed attempt keeps its selected questions and answers instead of changing them halfway through.

The developer console's **Lessons & exams → Lesson cards** editor edits teaching, examples, questions, answer choices, and the new note-parts/clef/tree pictures. Teacher-written or edited cards retain their own check instead of inheriting potentially unrelated built-in follow-ups. Older author drafts receive the new foundation cards once, tracked by `learningPathsVersion: 1`; existing edits and deletions are preserved. New exports preserve explicit foundation-card deletions too. Author drafts stay on the device until exported and published.

Short-section progress and basics quiz results use `codaClassroomLearningPathsV1`, a local-only, profile-scoped key. Partial checks save only a card ID and the number answered correctly, never question text or answer keys. Randomized quiz selections and ordering stay in the separate local `codaClassroomQuizAttemptsV1` key. Existing completed-card records remain valid for the same content revision. These checks do not create canonical quiz proof or XP. The complete category quiz uses the existing quiz records and once-only lesson reward. Existing earned achievements are retained; the cloud data format and Firebase rules are unchanged. Switching students clears this local practice, and returning to guest play restores the guest backup.
